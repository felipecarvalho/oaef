### Stack-Specific Architectural Rules (Python)

1. **Strict Anti-Suppression Policy**:
   - Suppressing linting, formatting, or type errors via `# noqa`, `# type: ignore`, or `# pylint: disable` is strictly forbidden.
   - **Permitted Scoped Deprecation Exception**: `# noqa: W1505`, `# noqa: B005`, `# pylint: disable=deprecated-method`, or `# type: ignore[deprecated]` is permitted solely when invoking deprecated APIs from external PyPI packages during transitional upgrades.
   - **Permitted Code-Gen Exception**: `# type: ignore` or `# noqa` is permitted solely at the top of automated code-generator outputs (matching `*_pb2.py` or containing `# Generated by`).
   - Blanket suppressions without specific error codes are strictly forbidden.

2. **Structural Pattern Matching**:
   - For discriminated unions, status dispatching, and command routing, use Python 3.10+ `match / case` syntax instead of long chains of `if/elif/else`.
   - Ensure pattern cases are exhaustive against domain models and enumerations.

3. **Strict Type Annotations (PEP 484 & PEP 585)**:
   - All function signatures, public methods, and dataclass/Pydantic fields must have explicit type annotations.
   - Untyped `*args` and `**kwargs` are prohibited in business domain layers.

4. **Exception Discipline**:
   - Bare `except:` or `except Exception: pass` is strictly prohibited.
   - Always catch specific exception classes and chain context using `raise DomainException(...) from err`.

5. **Pure Domain Logic & Modularity**:
   - Isolate side effects (network, file I/O, database) behind repository protocols. Domain logic functions must remain pure and deterministic.
