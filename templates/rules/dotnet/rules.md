### Stack-Specific Architectural Rules (C# & .NET)

1. **Strict Anti-Suppression Policy**:
   - Suppressing compiler warnings or Roslyn analyzer rules via `#pragma warning disable` or `[SuppressMessage(...)]` is strictly forbidden.
   - **Permitted Scoped Deprecation Exception**: `#pragma warning disable CS0618` or `CS0612` (with matching `#pragma warning restore`) is permitted solely when invoking obsolete APIs from external NuGet packages during active migration.
   - **Permitted Code-Gen Exception**: `<auto-generated />` headers or `[GeneratedCode]` attributes are permitted solely in compiler-generated code (e.g. Source Generators, protobuf).
   - Blanket `#pragma warning disable` without specific CS warning codes is strictly forbidden.

2. **Strict Nullable Reference Types**:
   - Always enable `<Nullable>enable</Nullable>` in project files.
   - Using the null-forgiving operator `!` is prohibited in business logic unless immediately preceded by a verified contract check.

3. **Modern C# Idiomatic Constructs**:
   - Use file-scoped namespaces (`namespace Project.Feature;`) to eliminate indentation clutter.
   - Use pattern matching `switch` expressions and primary constructors for clean class initialization.
   - Use `record` or `record struct` for immutable Data Transfer Objects (DTOs) and domain events.

4. **Asynchronous Discipline & Cancellation**:
   - Always accept and propagate `CancellationToken` in asynchronous methods.
   - Use `ValueTask<T>` on performance-critical hot paths where synchronous completion is frequent.

5. **Interface-Based Dependency Injection**:
   - Register dependencies against interfaces with explicit lifetimes (`AddScoped`, `AddSingleton`, `AddTransient`).
   - Domain logic must remain decoupled from specific infrastructure implementations.
